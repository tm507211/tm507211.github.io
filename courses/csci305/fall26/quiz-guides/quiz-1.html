Quiz 1 Study Guide

CSCI 305: Concepts of Programming Languages

This guide lists what you should be able to do, not the questions you will be asked. It ranges a little wider than the quiz itself, and covers Lectures 1–4 and their textbook chapters. Answers are short: a sentence or two, in your own words, earns full credit.

What to expect
When
At the start of class, on the date shown in the schedule.
Length
About 10 minutes.
Rules
Closed book, handwritten.
Format
A handful of short conceptual questions, plus one question that asks you to read a small Rust snippet and say what it evaluates to.
Answers
Explanations in your own words — no memorized dates or trivia.

Why an interpreter, and how languages got off the machine Lecture 1

Reading: Why build an interpreter? · From machine code to high-level languages  |  Slides: Lecture 1

Be able to:

  • Say what an interpreter does — map a program's structure to its meaning — and how that differs from what a compiler does.
  • Explain why a language is both a specification and an implementation, and why this course works where a program's meaning is visible rather than on translation.
  • Describe what makes a language low-level versus high-level, and what each step up (symbolic names for addresses, expressions, block structure) hands off from the programmer to the language.
  • Explain, in your own words, the problem that naming a storage location solves — why writing to a name is better than writing to a fixed absolute address.

Paradigms, and syntax versus semantics Lecture 2

Reading: The paradigm branches · Syntax and semantics  |  Slides: Lecture 2

Paradigms. Be able to:

  • Name the four paradigms (imperative, functional, declarative/logic, object-oriented) and give the one-line idea of what each takes a program to be.
  • Explain what actually decides a program's paradigm — what a language treats as primitive and lets you leave implicit — and why two languages with nearly identical syntax can belong to different paradigms.
  • Say what it means for a language to be multi-paradigm, with an example.

Syntax and semantics. Be able to:

  • Distinguish a syntax error from a semantics error, and a static check (before the program runs) from a dynamic one (while it runs) — and classify a given mistake.
  • Distinguish concrete syntax from abstract syntax, and explain why the same meaning can wear more than one concrete spelling.
  • Explain why a semantics is given as precise rules rather than English prose.

Rust I — the abstract syntax tree Lecture 3

Reading: The abstract syntax tree  |  Slides: Lecture 3

Be able to:

  • Explain what an AST records and what it drops relative to the source text.
  • Say how operator precedence shows up in the shape of the tree — which operator ends up at the root, and why.
  • Explain why an AST is naturally a sum type (a Rust enum, one variant per shape), and why recursive children are held behind a Box.
  • Say what a span is for and why every node carries one.
  • Read basic Rust: fn, let, enum, and a match over an enum — and state what a small example computes.

Rust II — values and runtime errors Lecture 4

Reading: Values and runtime errors  |  Slides: Lecture 4

Be able to:

  • Describe the space of values a program can evaluate to, and why it is a fixed, closed set (a tagged enum, one variant per kind of value).
  • Explain what a stuck evaluation is (e.g. adding a boolean to an integer, dividing by zero) and why such an expression has no value.
  • Explain why the evaluator returns a Result rather than a plain value, and what Result and Option each represent.
  • Say what the ? operator does when a sub-expression fails.
  • Distinguish the two kinds of failure kept apart in the interpreter: the host getting stuck (uncatchable) versus an ordinary in-language value that models a failure.
  • Read basic Rust: Option/Result and a match that handles each case.
How to practice
The single best rehearsal is the Concept Checks at the end of each textbook chapter — they are the same kind of short, conceptual question, with worked answers you can check yourself against. Work them with the answers hidden first. Re-reading the Lecture 1–4 slides and re-typing the small Rust snippets is the next most useful thing.

Terms you should be able to define in a sentence

  • interpreter vs. compiler
  • specification vs. implementation
  • low-level vs. high-level
  • symbolic address / named location
  • paradigm
  • multi-paradigm
  • imperative / functional / declarative / OO
  • syntax vs. semantics
  • syntax error vs. logic error
  • static vs. dynamic semantics
  • concrete vs. abstract syntax
  • grammar
  • abstract syntax tree (AST)
  • sum type / enum
  • Box (and why it’s needed)
  • span
  • match / exhaustiveness
  • value (tagged union)
  • stuck evaluation / runtime error
  • Result / Option / ?
