A Practical Introduction to Programming Language Design

Milestone M7

Algebraic Data Types and Pattern Matching

Part VIII gave Bridger a way to declare data and a way to take it apart. Sum and product types added type declarations and constructors. Pattern matching added match, guards, and ?, and Exhaustiveness checking added the premise of T-Match that requires the arms to cover their scrutinee’s type. This milestone builds all of it, and the prelude’s Option, Result, and Ordering constructors come to life with it. Every M1–M6 test must still pass.

The work is in three files you have already edited: the evaluator in src/interp/eval.rs, the checker in src/types/check.rs, and the rule checks in src/relations/check.rs.

Implementing Milestone M7

The provided runtime

A constructor value is Value::Ctor(name, args), with its arguments in an Rc<[Value]>. A list is Value::List(List), whose uncons returns the head and a reference to the tail. Keep the sharing: a :: or ...rest pattern binds the tail it was given, and cloning a List is cheap, whereas rebuilding one would make a recursion over a list quadratic. Pattern::binders in ast.rs lists the names a pattern binds. Finding a constructor’s declaration is a walk over Decl::Type entries in the program’s decls, whose variants carry their names and field types.

A struct declaration is Decl::Struct(generics, fields), and a struct value is Value::Struct(name, fields), with its fields as name and value pairs in an Rc<[(Name, Value)]>. No program can build one yet, since Expr::Struct is a todo_m8!, so at this milestone only the checker and exhaustiveness halves of a struct pattern can run against a real struct. Against any other value, the matcher’s struct arm reports that the value does not fit.

The evaluator’s arms

  • Ctor decides what its name means before it runs the arguments. With no arguments, a name that is Int, Bool, String, or a declared type or struct is the type itself, a Value::Type, which M8’s associated calls use as a receiver. Any other declared name that is not a constructor is NotAFunction, with found the named type type N. A name that is not declared is UnboundVariable. It then evaluates the arguments left to right and checks the argument count afterward, reporting ArityMismatch at the whole expression if the count differs from the declaration.
  • The matcher is one recursive function following match(p,v). A value that does not fit is an ordinary result that sends the evaluator to the next arm, and it never becomes a RuntimeError. Its literal arm compares the value it is given with the value the literal denotes.
  • Match evaluates the scrutinee once, then tries the arms in order. Each arm’s bindings extend the environment at the match, for that arm’s guard and body. A guard that is not a Bool is TypeError { expected: Bool, found, span } at the guard, with found from type_of. After the last arm, the result is NonExhaustiveMatch at the match.
  • Try returns the argument of an Ok or Some. On a None or an Err, it raises Control::Return holding that same value, the signal your return arm uses, so the enclosing function’s call handles it. Any other value is NonExhaustiveMatch at the ?.

The checker’s arms

Each arm ends as M5’s did, with the final unification against the expected type and the record.

  • Ctor looks the name up as the table says, with the wrong-arity report made before any argument is checked. It maps the declaration’s type parameters to fresh inference variables, records any declared bound with require_trait as your Var arm does, and builds the constructed type. If the expected type has the same head, unify with it now, so that an argument such as an unannotated lambda is checked against a known type. Each argument is then checked against its field’s type with the map applied.
  • check_pattern takes a pattern, the scrutinee’s type, and a context to extend. It also needs to know which variables this pattern has bound so far, to raise NonLinearPattern at the second occurrence and to compare the sides of an |. A ...rest binder goes through the same path as a variable, at the type of the list. An | checks each side on its own context. Both must bind the same names, and their types must unify, or the result is OrPatternBindings at the whole pattern. A struct pattern looks its name up first. It then rejects a repeated field, and instantiates the declaration’s type parameters as a constructor pattern does before unifying with the scrutinee’s type. Each named field’s pattern is checked against that field’s type with the map applied, and an undeclared field is NoSuchField at the field’s pattern. Every mismatch is reported at the pattern’s own span. In a Mismatch, the scrutinee’s type is expected and the pattern’s is found.
  • Match checks the scrutinee with no expected type. If the scrutinee diverges, call dead_after with the scrutinee’s span and the span of the match. The result type is the expected type if there is one, or a fresh variable. Each arm checks, on its own copy of the context, its pattern, its guard against Bool, and its body against the result type. Exhaustiveness comes after every arm, so a disagreeing arm is reported ahead of a gap: when is_exhaustive is false, the result is NonExhaustiveMatch at the match. If there is at least one arm and every body diverges, call record_diverging on the match.

Try

? checks its operand with no expected type. An operand that diverges calls dead_after and the form takes a fresh variable. After resolving the operand’s type:

  • A Result<T, E> requires the context’s return type, ctx.ret(), to unify with a Result of some fresh T' and E'. No return type at all is ReturnOutsideFunction, and a return type that will not unify is TryInNonCarrierFunction { ret, span }, or TryInLambda { found: ret, span } when ctx.in_lambda() holds. Then E must unify with E', and if it does not, the result is Mismatch { expected: E', found: E, span }. The form’s type is T.
  • An Option<T> is the same with Option in place of Result, and has no error type to compare.
  • An unsolved inference variable is Ambiguous, unless in_dead_code holds for the form, where it takes a fresh variable. Any other type is TryOnNonCarrier { found, span }.

If the return type is an inference variable when ? constrains it, call note_try_pinned with its id. The Lambda arm reads that back through try_pinned. When a lambda has no written result type, a ? inside it pinned the inference variable for that result type, and checking the lambda’s body fails with a Mismatch whose expected type is that pinned result type, replace the error with TryInLambda using the same found type and span. Any other error from the body stays as it is.

Exhaustiveness

Exhaustiveness checking defines the check, and its summary of the parts divides it into a reduction of patterns to wildcards, constructors, and alternatives; a function from a type to its signature; and U with its helpers S and D. The module below provides U, S, and D. You write the reduction and the signature, and the method that joins them.

Paste the module at the end of src/types/check.rs, unchanged, and add use exhaustive::{Con, Pat, Signature}; to the file’s imports. Its public function is covers(rows, ty, signature), which holds when no value of ty escapes every row, with one Pat per row. It asks signature for the constructors of each column’s type as S replaces a column by a constructor’s arguments, so the column types and the splitting of | alternatives happen inside it. Within the module, useful is U, specialize is S, and default_rows is D. Nothing reaches the module until your code calls covers, which is why it allows dead_code.

/// Provided helpers (Milestone M7): the usefulness test behind
/// exhaustiveness checking. Paste this module at the end of the file,
/// unchanged. Until `is_exhaustive` calls `covers`, nothing reaches this
/// module, so `dead_code` is allowed here.
#[allow(dead_code)]
pub mod exhaustive {
    use crate::ast::{Name, Ty};
    use std::collections::HashSet;

    /// A pattern as the usefulness test sees it: a wildcard, a constructor
    /// applied to sub-patterns, or two alternatives. A variable is a
    /// wildcard here, since it matches anything.
    #[derive(Clone, Debug)]
    pub enum Pat {
        Wild,
        Con(Con, Vec<Pat>),
        Or(Box<Pat>, Box<Pat>),
    }

    /// The constructor at the head of a pattern. Literals are constructors
    /// with no arguments; a tuple of width n is one constructor of arity n;
    /// a list is `Nil` or `Cons(head, tail)`; a struct is one constructor
    /// whose arguments are its fields in declaration order.
    #[derive(Clone, Debug, PartialEq, Eq, Hash)]
    pub enum Con {
        Int(i64),
        Bool(bool),
        Str(String),
        Unit,
        Tuple(usize),
        Nil,
        Cons,
        Ctor(Name),
        Struct(Name),
    }

    /// A type's constructors, each with its argument types.
    pub type Signature = Vec<(Con, Vec<Ty>)>;

    /// The function `covers` asks for a type's signature: `None` for a type
    /// that only a wildcard covers (`Int`, `String`, a function, ...).
    pub type SignatureOf<'a> = dyn Fn(&Ty) -> Option<Signature> + 'a;

    /// One row of the pattern matrix: a pattern per column.
    type Row = Vec<Pat>;

    /// Whether the rows cover every value of `ty`: no value of that type
    /// escapes all of them.
    pub fn covers(rows: &[Pat], ty: &Ty, signature: &SignatureOf<'_>) -> bool {
        let matrix: Vec<Row> = rows.iter().map(|p| vec![p.clone()]).collect();
        !useful(&matrix, &[Pat::Wild], std::slice::from_ref(ty), signature)
    }

    /// Whether some value (of `tys`, one type per column) matches `q` and
    /// no row of `rows`.
    fn useful(rows: &[Row], q: &[Pat], tys: &[Ty], sig: &SignatureOf<'_>) -> bool {
        let Some((head, q_rest)) = q.split_first() else {
            return rows.is_empty();
        };
        let (ty, tys_rest) = (&tys[0], &tys[1..]);
        // Continue with `pats` in place of the first column.
        let go = |rows2: &[Row], pats: Vec<Pat>, arg_tys: Vec<Ty>| {
            let mut q2 = pats;
            q2.extend_from_slice(q_rest);
            let mut tys2 = arg_tys;
            tys2.extend_from_slice(tys_rest);
            useful(rows2, &q2, &tys2, sig)
        };
        match head {
            Pat::Or(a, b) => {
                go(rows, vec![(**a).clone()], vec![ty.clone()])
                    || go(rows, vec![(**b).clone()], vec![ty.clone()])
            }
            Pat::Con(c, args) => {
                let arg_tys = arg_types(sig(ty), c, args.len());
                go(&specialize(rows, c, args.len()), args.clone(), arg_tys)
            }
            Pat::Wild => {
                let heads = head_constructors(rows);
                let complete = sig(ty).filter(|cons| is_complete(cons, &heads));
                match complete {
                    Some(cons) => cons.into_iter().any(|(c, arg_tys)| {
                        let rows2 = specialize(rows, &c, arg_tys.len());
                        go(&rows2, vec![Pat::Wild; arg_tys.len()], arg_tys)
                    }),
                    None => useful(&default_rows(rows), q_rest, tys_rest, sig),
                }
            }
        }
    }

    /// Constructor `c`'s argument types, or `n` placeholders when the type
    /// has no signature (a literal of `Int` or `String`).
    fn arg_types(sig: Option<Signature>, c: &Con, n: usize) -> Vec<Ty> {
        let found = sig.and_then(|s| s.into_iter().find(|(k, _)| k == c));
        match found {
            Some((_, tys)) => tys,
            None => vec![Ty::meta(u32::MAX); n],
        }
    }

    /// Whether every constructor of a (non-empty) signature heads some row.
    fn is_complete(sig: &Signature, heads: &HashSet<Con>) -> bool {
        !sig.is_empty() && sig.iter().all(|(c, _)| heads.contains(c))
    }

    /// Every constructor at the head of some row, alternatives flattened.
    fn head_constructors(rows: &[Row]) -> HashSet<Con> {
        fn heads(p: &Pat, out: &mut HashSet<Con>) {
            match p {
                Pat::Wild => {}
                Pat::Con(c, _) => {
                    out.insert(c.clone());
                }
                Pat::Or(a, b) => {
                    heads(a, out);
                    heads(b, out);
                }
            }
        }
        let mut out = HashSet::new();
        for p in rows.iter().filter_map(|row| row.first()) {
            heads(p, &mut out);
        }
        out
    }

    /// The rows specialized to constructor `c` of arity `n`: a row headed
    /// by `c` gives its arguments then its other columns, a row headed by a
    /// wildcard gives `n` wildcards then its other columns, and a row headed
    /// by another constructor is dropped.
    fn specialize(rows: &[Row], c: &Con, n: usize) -> Vec<Row> {
        let mut out = Vec::new();
        for row in rows {
            let Some((head, rest)) = row.split_first() else {
                continue;
            };
            match head {
                Pat::Con(k, args) if k == c => {
                    out.push([args.as_slice(), rest].concat());
                }
                Pat::Con(..) => {}
                Pat::Wild => {
                    let wilds = vec![Pat::Wild; n];
                    out.push([wilds.as_slice(), rest].concat());
                }
                Pat::Or(a, b) => {
                    for alt in [a, b] {
                        let r = [std::slice::from_ref(&**alt), rest].concat();
                        out.extend(specialize(&[r], c, n));
                    }
                }
            }
        }
        out
    }

    /// The rows headed by a wildcard, without that column.
    fn default_rows(rows: &[Row]) -> Vec<Row> {
        let mut out = Vec::new();
        for row in rows {
            let Some((head, rest)) = row.split_first() else {
                continue;
            };
            match head {
                Pat::Wild => out.push(rest.to_vec()),
                Pat::Con(..) => {}
                Pat::Or(a, b) => {
                    for alt in [a, b] {
                        let r = [std::slice::from_ref(&**alt), rest].concat();
                        out.extend(default_rows(&[r]));
                    }
                }
            }
        }
        out
    }
}

covers takes the signature function as a closure over the checker, written &|t| self.signature(t). A test will also hold you to these points:

  • Option<Bool> is completed by Some(true), Some(false), and None only if signature applies the type’s arguments to its constructors’ field types.
  • Int and String have literals but no signature, so a match over either needs an arm that matches anything.

A struct has a single constructor, so one struct pattern covers its type when the patterns for its fields cover theirs. The M8 tests hold you to this, once struct values exist.

Guards

check_guards visits every fn body, global initializer, impl method, and rule conjunct. It reports the first offender in source order, sorted by source and position, since the order of decls is not the order of the file. Within a body, a match’s own guards come before those nested further in. The walker from M6’s helper module already yields guards.

Each guard is judged by your M6 purity judgment, with its pattern variables as locals, and with one difference from a rule filter: recursion is allowed, because a guard runs once per arm and need not contribute to a fixpoint. A guard that reaches a function with a function-typed parameter is HigherOrder, as a filter is. An impure guard is ImpureGuard { span, witness }, at the guard, with the chain of calls to the effect. A call through a local closure g has the witness ["g"].

How to know it works

cargo m7 runs the provided milestone M7 tests and, with them, every earlier milestone’s. Some run a whole program with run_program, which skips the static checks, so the evaluator meets programs the checker would have refused. Some call Checker::check_program on a loaded program, and some call check_guards alone. A rejection is tested by its error variant and, where it matters, by its payload, and the text of a message is never tested.

Write the matcher and the evaluator’s arms first, since the whole-program tests reach them without the checker. Then write check_pattern and the checker’s arms with an is_exhaustive that returns true, and fill in the check once the rest passes. check_guards can come at any point after that.

Design problems

Write a compiler from Arith to a stack machine, with instructions Push(Int), AddTop, and MulTop, and a function run that executes a list of instructions on a stack and returns Option<Int>. Argue that it agrees with value. 
type Arith = Num(Int) | Add(Arith, Arith) | Mul(Arith, Arith);
type Instr = Push(Int) | AddTop | MulTop;

fn compile(e: Arith) -> [Instr] = match e {
    Num(n) => [Push(n)],
    Add(l, r) => compile(l) ++ compile(r) ++ [AddTop],
    Mul(l, r) => compile(l) ++ compile(r) ++ [MulTop],
};

fn run(code: [Instr], stack: [Int]) -> Option<Int> = match (code, stack) {
    ([], [top]) => Some(top),
    ([], _) => None,
    (Push(n) :: rest, s) => run(rest, n :: s),
    (AddTop :: rest, b :: a :: s) => run(rest, (a + b) :: s),
    (MulTop :: rest, b :: a :: s) => run(rest, (a * b) :: s),
    (_ :: _, _) => None,
};

run(compile(Add(Num(3), Mul(Num(4), Num(2)))), []) is Some(11). Without the last arm the checker rejects run, because the value (AddTop :: [], []) fits no arm: an instruction that needs two operands on a stack that has too few.

The claim to prove is stronger than the one asked for, since compile(l) runs with instructions after it and values under it. For every e, k, and s, run(compile(e) ++ k, s) equals run(k, value(e) :: s). The proof is by induction on e, with one case per constructor. Num(n) is one Push step. For Add(l, r), the induction hypothesis applied to l and then r leaves value(r) :: value(l) :: s, and AddTop replaces those with their sum. Taking k as [] and s as [] gives the result. The recursion in compile, the cases of the proof, and the arms of the match all follow the alternatives of the declaration.

Given type Nat = Zero | Succ(Nat); and relation p : (Nat);, the rule rule p(Succ(x)) :- p(x); does not parse, because a rule's arguments are variables and literals. Suppose it did. What would happen to the fixpoint, and is a constructor in a rule body any safer?

With add p(Zero), the rule derives Succ(Zero), then Succ(Succ(Zero)), and so on with no end. Evaluating relations guaranteed termination because every value in a derived fact already occurs in some fact, which leaves a finite set of possible facts. A constructor in a head builds values that occur nowhere, so that set is infinite and the rounds never finish. This is the difference between Datalog and Prolog, whose terms may be compound and whose programs need not terminate.

A constructor pattern in a body position, as in rule q(x) :- p(Succ(x));, only takes existing values apart. Every x it binds is a part of a value already present, and the parts of a finite set of finite values are finite, so termination would survive. Matching would have to look inside values, which makes unify a little more than the comparison of variables and constants that it is now. Facts can already hold constructor values today, and a rule filter can open them with a match.

Bridger accepts a match with an arm that can never run. Using usefulness, say how to detect such an arm, trace it on arms Some(x), None, Some(1), _, and say how guards change the answer.

Arm j can run exactly when U(P1..j−1​,pj​) holds, where P1..j−1​ has a row for each earlier arm. For Some(1), the earlier rows are Some(x) and None. The head of q is the constructor Some, so U specializes: the row None drops, the row Some(x) becomes a wildcard, and q becomes 1. Specializing again by the literal 1, the wildcard row leaves a row with no columns and q has none either. A row remains, so U is false and the arm can never run. For _, the rows Some(x), None, and Some(1) make the heads complete. Specializing by Some leaves the rows and 1, whose heads are incomplete, and D keeps the wildcard row, so U is false. Specializing by None leaves a row with no columns, also false. _ can never run either.

A guarded earlier arm contributes no row, since its guard may fail. A guarded arm is still tested by its own pattern: if the pattern is useless, the guard cannot help it. An unreachable arm is usually a mistake, such as a general arm written above a specific one, and many compilers warn about it. Bridger could add such a warning and still accept the same programs.
